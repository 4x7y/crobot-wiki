Walkthrough: hybrid control in simulation

Source: examples/hybrid_control/main.cpp. This experiment loads the UR5 scene and demonstrates position, force and impedance control with TaskSpaceController.

Run it

From the checkout root:

cmake --build build --target hybrid_control --parallel 2
cd build
./bin/hybrid_control -c position

Close the window and rerun with -c force or -c impedance. The default is force. -h prints usage. A display is required, and the working directory must be build/ because the XML path is ../resources/ur5/ur5.xml.

Follow the data

  1. The constructor obtains the robot and link6 body. It registers contact between the ee and floor geometries.

  2. The tool point is a body-local offset (-0.2, 0, 0) with a specified task rotation. A WorldFrame stores the desired pose.

  3. PoseTrajectory and TrapvelTimeScaling generate a reference between two transforms over 100 seconds.

  4. Force/impedance mode selects motion directions {0, 1, 2, 3, 4} and force direction {5}, with desired force -3.0 in that task direction.

  5. Generalized IK computes an initial configuration. Each control callback then updates desired pose/velocity/acceleration, reads live joint state, computes the command and writes it with set_ctrl_mj.

  6. visualize draws the task frame and arrows for the measured/desired force.

Direction 5 is the third translational axis in the configured task frame. Its sign must be interpreted using that frame, not simply the world’s vertical axis. The example changes the initial position in position-only mode, so the three modes do not have identical initial conditions.

What to change first

Change only the trajectory endpoints or duration, then inspect the frame marker and tracking response. For force mode, verify contact activation and direction before adjusting the force magnitude. A pose target in one frame and a force in another can produce a plausible-looking but incorrect experiment.

When adapting this source, add a check of the initial IK return value before applying get_qpos(). Its fixed m_dt = 0.02 also differs from the scene’s 0.002 physics timestep. Since the callback runs on physics steps, the reference clock advances 10 times as fast as simulated time. Use simulation time/timestep or deliberate controller decimation with consistent reference derivatives. See B09: Hybrid-control reference time advances ten times too fast and B10: Hybrid-control startup applies an unchecked IK result.

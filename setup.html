Set up and build

Run repository commands from the checkout root unless a step explicitly changes directory. The supported compiler path in the root CMake file is GCC with C++17. Its declared CMake minimum is 3.10.2, but some example projects require 3.14; use the CMake supplied with the lab environment.

Get the checkout

If you do not yet have the source, use the repository named in the project README:

git clone https://github.com/4x7y/crobot.git
cd crobot

Use the lab’s agreed branch or revision for a shared experiment and record it with your results. The following paths are relative to this checkout.

Use a lab environment

The repository supplies Docker Compose recipes under docker/. The olympic recipe names image isurobolab/crobot:olympic and container crobot_olympic; yosemite uses isurobolab/crobot:yosemite and crobot_yosemite. These are names in the checked-in recipes, not a guarantee that a remote image contains every dependency required by this checkout.

For a workstation already arranged for the Olympic recipe:

cd docker/olympic
docker compose up -d
docker exec -it crobot_olympic bash
cd /ws

Older installations may use docker-compose in place of docker compose. Inspect the recipe’s volume mappings first: it expects the checkout and several sibling ROS packages at particular paths. It also enables host networking, device access and X11 forwarding for lab use. A numerical-only development session does not need to launch a robot service. Display access is needed only for the viewer exercises.

Build the C++ library

From the checkout root inside an environment with the dependencies installed:

cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCROBOT_BUILD_PYTHON_BINDINGS=OFF
cmake --build build --parallel 2
cmake --build build --target hello_world model_info --parallel 2
./build/bin/hello_world
./build/bin/model_info

hello_world prints a log message. model_info constructs and prints a small body tree; neither opens a viewer or connects to hardware. Examples and tests are excluded from the default build, so request their targets explicitly. Use a small parallel job count if compilation exhausts memory.

The configure step generates build/crobot/config.hpp and umbrella headers such as build/crobot/kdl/kdl.hpp. Library output goes to build/lib; in-tree examples normally go to build/bin. Keep both the source and build include roots when compiling custom code; CMake targets handle this for you.

Dependencies and options

All 15 source modules are added by crobot/CMakeLists.txt. A dependency being labelled “optional” in configure output does not imply that every consuming module is disabled when it is missing. There is no general set of per-module CROBOT_BUILD_* switches in this checkout.

Use cmake/FindDependencies.cmake, module CMake files, and the selected Docker recipe to resolve a missing package. A guessed package list from an older Ubuntu installation is not a substitute for these requirements.

Useful configure settings

Setting

Default and effect

CMAKE_BUILD_TYPE

Release; choose RelWithDebInfo for debugging optimized code.

BUILD_SHARED_LIBS

ON; controls shared versus static libraries.

CROBOT_BUILD_PYTHON_BINDINGS

ON; turn off for the first C++ build, or follow Python bindings.

CROBOT_VERBOSE

ON; prints configuration details.

CMAKE_INSTALL_PREFIX

Destination for an installed C++ library and resources.

CROBOT_ASSERT_ENABLED exists, but the root build also defines it to 1 unconditionally. Do not assume switching the cache option off disables checks. CROBOT_BUILD_EXTRAS is declared but does not gate the example directories.

Link your own program

For a new program inside this source tree, follow an example CMake file and link only the component targets you use. A minimal standalone project using an installed library looks like this:

cmake_minimum_required(VERSION 3.14)
project(lab_model LANGUAGES CXX)
find_package(CROBOT CONFIG REQUIRED COMPONENTS kdl)
add_executable(lab_model main.cpp)
target_compile_features(lab_model PRIVATE cxx_std_17)
target_link_libraries(lab_model PRIVATE crobot-kdl)

Configure with -DCMAKE_PREFIX_PATH=/path/to/crobot/install. Exported target names are crobot and crobot-<module>, without a CROBOT:: prefix. Some older component exports do not declare all transitive dependency packages; if CMake reports a missing imported target, inspect the component’s target_link_libraries and find that dependency in the consuming project. The in-tree build is the most direct starting point for lab development.

Build the manual independently

No robot SDK or C++ compilation is needed to build this guide:

python3 -m venv /tmp/crobot-docs-venv
/tmp/crobot-docs-venv/bin/python -m pip install -r docs/source/requirements.txt
/tmp/crobot-docs-venv/bin/python -m sphinx -n -W --keep-going -b html docs/source docs/build/html

Open docs/build/html/index.html. See Develop and maintain CRobot for catalogue checks and the separate Doxygen API build.

How the library fits together

CRobot has three useful entry points. kdl::RigidBodyTree represents a robot without requiring a running simulator. simulation::MJSim loads a MuJoCo scene and exposes a compatible MJRBTree. geometry::MeshIO starts the object-processing pipeline without requiring a robot model.

A typical manipulation experiment loads a model, chooses contact points, solves IK for a starting configuration, generates a reference trajectory, and computes commands from measured state. Simulation and hardware are different ways of supplying measurements and applying those commands.

Robot model ──► KDL ──► IK ──► trajectories / actions ──► controllers
                  ▲                                      │
                  └────── MuJoCo state and commands ──────┘

Triangle mesh ──► geometry ──► patch_tree ──► grasping
                                  │             │
                                  └── optimization solvers

Measurements + dynamics ──► ekf ──► estimated object state

These are workflow relationships. The actual link dependencies live in each module’s CMakeLists.txt; for example, control links to IK and planning, and hardware also links to simulation.

Repository layout

crobot/ contains reusable library code. examples/ contains executable experiments, often tied to particular models, datasets or ROS packages. resources/ contains model XML, meshes and configuration data. unittests/ and python/tests/ supply executable examples of expected behavior. python/src/ defines the binding surface; it is smaller than the C++ library. cmake/ contains dependency discovery and installed component exports. docker/ contains lab environment recipes. docs/source/ is this guide; doxygen/ configures the separate C++ API browser.

What to learn first

Before changing an experiment, be able to identify its model file, body and joint names, state-vector dimensions, target coordinate frame, command units, and runtime working directory. Use show_details() and the source rather than assuming that two robots share an index layout.

Keep reusable algorithms in crobot/ and experiment wiring in examples/. The catalogue includes unfinished interfaces, but their presence is not a promise that they are ready for use; the relevant guides identify known stubs.

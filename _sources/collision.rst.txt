Collision geometry and queries
==============================

Link target: ``crobot-collision``. Namespace: ``crobot::collision``. This module
uses HPP-FCL; it is separate from MuJoCo's contact engine. See
:doc:`api/collision` for its two header/implementation pairs.

``geometry.hpp`` aliases HPP-FCL shapes (``Sphere``, ``Box``, ``Capsule``,
``Cylinder``, ``Ellipsoid``, ``Plane`` and a BVH ``Mesh``), collision objects and
transforms. ``to_fcl_transform`` and ``from_fcl_transform`` convert homogeneous
transforms. ``create_mesh(vertices, triangles)`` constructs mesh collision
geometry from an N×3 vertex array and an M×3 triangle-index array.

``CollisionBody`` stores named shapes with their local transforms. Add a
primitive with ``add_geom_sphere`` or ``add_geom_box``, or supply geometry with
``add_collision_geometry``. ``get_geom(name)`` returns the shape and its local
transform; place the shape in the intended world frame before a query.

The executable ``collision_checking`` and ``unittests/unit/test_collision.cpp``
show pairwise collision/distance calls using the HPP-FCL types. The
example creates two boxes directly and needs neither a model file nor a display.
Build and run it from the checkout root:

.. code-block:: bash

   cmake --build build --target collision_checking --parallel 2
   ./build/bin/collision_checking

Collision shape pose and visual mesh pose are independent unless your code
keeps them synchronized. Use the same scale and frame conventions for both.
Adding collision geometry does not automatically make a planner collision-aware:
:doc:`planning` describes the validity methods that must perform the queries.
For forces generated by MuJoCo contacts, use :doc:`simulation` instead.

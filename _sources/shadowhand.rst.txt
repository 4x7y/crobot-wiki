Shadow Hand model and calibration helpers
=========================================

Headers: ``crobot/hardware/shadow_*.hpp``. Namespace: ``crobot::hardware``.
These classes connect the hand's model, joint ordering, motors, fingers and
calibration information. They do not themselves implement the complete ROS
command transport.

Construct ``ShadowHand::MakeShared(model)`` with the intended model, or use the
default factory. The default model comes from the checked-in Shadow MuJoCo
resource. ``shadow_hand.cpp`` also constructs a static simulation during library
loading, so that resource path matters even before a hand operation is called.

``get_model`` returns the robot model. ``get_finger`` selects configured fingers
such as ``rh_ff`` and ``rh_th``; validate the name first.
``get_joint_names`` returns model joint names, while the ROS-specific limit
methods use the adapter's ROS ordering. ``print_details`` helps inspect the
configuration. Do not assume the model, ROS and motor vectors have identical
orders or lengths; use named mapping.

Supporting classes
------------------

``ShadowConfig`` assembles fingers from model data. ``ShadowFinger`` connects
joint/motor geometry to fingertip behavior; ``ShadowJoint`` and ``ShadowMotor``
represent the corresponding mechanisms. ``ShadowSensorProfile`` handles sensor
profiles, and ``TensionFriction`` supports tendon friction modeling. Calibration
files under ``resources/shadow_calibration`` are part of the experiment inputs.

Force estimation depends on the actual Jacobian, tendon/motor mapping and
friction parameters. A naive inverse of a fingertip Jacobian is not guaranteed
to exist or produce a force consistent with contact constraints. Trace the
finger implementation and its calibration data when changing this pipeline.

``shadow_hand_test``, ``shadow_torque_calibration`` and
``finger_data_processing`` are useful source references, but their ROS/device
and dataset requirements differ. Inspect each example's CMake and main program.
For simulated fingertip targeting, start with ``robot_ik`` and :doc:`ik`.

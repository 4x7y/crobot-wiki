Barrett WAM adapter
===================

Header: ``crobot/hardware/wam.hpp``. ``WamArm`` is declared in the **global
namespace**. The implementation targets a four-joint WAM protocol over sockets,
not an arbitrary ROS topic interface.

``WamArm::instance()`` returns the singleton. ``initialize(open_stream)`` sets
up the adapter; ``connect`` and ``close`` manage the connection. Endpoint and
protocol details live in ``wam.cpp``/``wam.hpp`` and must match the controller
server used by the lab.

Mode-specific commands
----------------------

``move`` and ``move_home`` request joint motion. Position, velocity and torque
streaming each have explicit start/end methods and matching setters:
``start_position_control``/``set_position``/``end_position_control`` and the
corresponding velocity and torque methods. Select the intended device mode
before sending commands. Joint vectors have four entries.

``request_position``, ``request_velocity``, ``request_pos_vel`` and the extended
state requests obtain feedback. ``start_pos_vel_stream`` and
``update_pos_vel_from_stream`` provide streamed feedback; stop it with
``end_pos_vel_stream``. Check integer status codes before treating output
vectors as fresh measurements.

The source contains connection/stream management, not a general real-time
scheduler or collision supervisor. Use the current lab controller startup and
stop procedure. ``examples/wam_test`` and WAM-specific control experiments may
command the physical arm; inspect their source with the operator before running.
Historical ROS Hydro installation instructions are not prerequisites for using
this C++ library in the current development environment.
